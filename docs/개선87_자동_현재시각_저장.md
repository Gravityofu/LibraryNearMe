# 개선87: 대출/반납일을 손대지 않았다면 항상 "처리하는 그 순간"의 날짜·시간으로 저장하기

## 목표

지금은 대출일/반납일 입력 칸이 화면을 열 때 딱 한 번 "오늘 날짜"로 채워지고, 그 이후로는 화면이 저절로 다시 계산하지 않습니다. 그래서 화면을 자정 전에 열어두고 자정을 넘긴 뒤에 그대로 대출·반납 처리를 하면, 실제로는 다음 날인데도 입력 칸에는 여전히 전날 날짜가 남아있어서 날짜가 하루 어긋나게 저장되는 문제가 있었습니다.

이 가이드는 "관리자가 '대출/반납일 변경'으로 직접 날짜를 바꾼 경우"와 "그냥 기본값 그대로 둔 경우"를 구분해서, 직접 바꾸지 않았다면 항상 처리하는 바로 그 순간의 실제 날짜·시간을 사용하도록 고칩니다. 반대로 관리자가 직접 날짜를 지정한 경우(예: 지난 대출 기록을 나중에 입력할 때)는 지금처럼 그 지정한 날짜가 그대로 쓰입니다.

## 4단계: 대출/반납 처리 시, 직접 지정하지 않았다면 날짜를 아예 보내지 않기

아래 내용을 찾으세요.

```typescript
        body: JSON.stringify({ userId: selectedMember.id, registrationNo: regNo, loanDate: loanDateStr }),
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
        body: JSON.stringify({
          userId: selectedMember.id,
          registrationNo: regNo,
          // 관리자가 '대출/반납일 변경'으로 직접 날짜를 지정했을 때만 그 날짜를 보냅니다.
          // 직접 지정하지 않았다면 날짜를 아예 보내지 않아서, 서버가 처리하는 바로 그 순간의
          // 실제 날짜·시간을 그대로 쓰게 합니다.
          loanDate: loanDateManuallySet ? loanDateStr : undefined,
        }),
```

이어서 아래 내용을 찾으세요.

```typescript
        body: JSON.stringify({ registrationNo: regNo, returnDate: returnDateStr }),
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
        body: JSON.stringify({
          registrationNo: regNo,
          // 관리자가 '대출/반납일 변경'으로 직접 날짜를 지정했을 때만 그 날짜를 보냅니다.
          // 직접 지정하지 않았다면 날짜를 아예 보내지 않아서, 서버가 처리하는 바로 그 순간의
          // 실제 날짜·시간을 그대로 쓰게 합니다.
          returnDate: returnDateManuallySet ? returnDateStr : undefined,
        }),
```

**설명:** `JSON.stringify`는 값이 `undefined`인 항목을 자동으로 빼고 보냅니다. 그래서 관리자가 날짜를 직접 바꾸지 않았다면 `loanDate`/`returnDate` 항목 자체가 서버로 전달되지 않고, 서버(`loans.controller.ts`)는 이미 "값이 없으면 처리하는 순간의 실제 날짜·시간을 쓴다"는 로직을 갖고 있으므로 별도로 백엔드를 고칠 필요는 없습니다. 반대로 관리자가 직접 날짜를 지정했다면 지금처럼 그 날짜가 그대로 전달됩니다.

## 확인하기

1. `frontend` 서버를 재시작해 주세요.
2. 대출/반납 화면을 새로고침 없이 켜 둔 상태에서, 컴퓨터의 시스템 날짜를 다음 날로 바꿔보세요. (테스트 목적으로만 잠시 바꾸고, 확인 후 원래대로 되돌려주세요.) 화면의 대출일 입력 칸은 여전히 이전 날짜를 보여주고 있어야 정상입니다(화면이 자동으로 새로고침되지 않으니까요).
3. 그 상태에서 회원을 선택하고 대출 처리를 해보세요. 데이터베이스(Prisma Studio 등)에서 확인했을 때, 화면에 보이던 이전 날짜가 아니라 실제로 처리한 시점(바뀐 시스템 날짜)의 날짜·시간으로 저장되어야 합니다.
4. '대출/반납일 변경' 버튼으로 날짜를 직접 다른 날짜로 지정한 뒤 대출/반납 처리를 해보세요. 이번에는 지정한 그 날짜로 정확히 저장되어야 합니다. (시스템 날짜는 다시 원래대로 되돌려놓고 확인해 주세요.)
5. 평소처럼(날짜를 건드리지 않고) 대출/반납 처리를 했을 때도 여전히 정상적으로 처리되는지 확인해 주세요.
