# 개선135: 키워드 삭제 버튼, 게시판 목록 행 전체 클릭, 시간 저장 방식 설명

## 목표

1. 관리자 게시판 글쓰기 화면에서, 입력한 키워드 칸을 하나씩 지울 수 있는 'x' 버튼을 추가합니다.
2. 홈페이지의 목록형(표 형태) 게시판에서, 제목뿐 아니라 행 전체 어디를 클릭해도 글 상세 페이지로 이동하게 합니다.
3. 데이터베이스에 저장된 시각이 `"2026-08-04T10:53:04.839Z"`처럼 "Z"가 붙은 형태로 보이는 이유를 설명해 드립니다. (결론: 코드를 고칠 필요가 없는, 정상적이고 오히려 더 안전한 저장 방식입니다.)

---

## 먼저: 데이터베이스에 보이는 시각에 대한 설명

질문하신 `"2026-08-04T10:53:04.839Z"`라는 값에서 맨 끝의 `Z`는 "이 시각은 UTC(협정 세계시) 기준으로 표기된 것"이라는 뜻입니다. 한국 시간은 UTC보다 9시간 빠르므로, `10:53`(UTC)은 정확히 한국 시간 `19:53`(오후 7시 53분)과 같은 순간을 가리킵니다. 화면에서 한국 시간으로 정확하게 보이셨다면, 이 값은 잘못된 게 아니라 **정확히 맞게 저장된 것**입니다.

조금 더 설명드리면, 컴퓨터 프로그램의 세계에서 "시각"은 보통 하나의 절대적인 순간(우주 어디서 보든 같은 시점)으로 다루고, 이걸 문자로 표시할 때 어떤 지역의 시계로 보여줄지는 표시하는 쪽(화면)에서 정하는 것이 표준적인 방식입니다. JSON으로 데이터를 주고받을 때 자바스크립트가 시각을 문자로 바꾸면 항상 이렇게 `Z`가 붙은 UTC 형태로 통일해서 보여주는데, 이건 자바스크립트의 정해진 규칙이라 저희가 바꿀 수 있는 부분이 아니고, 바꿔서도 안 됩니다.

만약 억지로 "한국 시간 그대로"(예: `2026-08-04T19:53:04+09:00`처럼 이름 뒤에 한국 시각 숫자를 그대로) 저장하도록 바꾼다면, 오히려 이후에 그 값을 가지고 "얼마나 시간이 지났는지" 계산하거나, 다른 나라 시간대와 비교하거나, 순서대로 정렬하는 것이 더 까다롭고 실수하기 쉬워집니다. 그래서 "저장은 항상 UTC 기준 절대 시각으로 하고, 화면에 보여줄 때만 한국 시간으로 바꿔서 보여준다"는 지금 방식이 세계적으로 통용되는 정석입니다. 개선134에서 화면 표시(`formatKstDateTime`)와 데이터베이스 접속 시간대(한국 시간 옵션 추가)를 모두 손봐드렸기 때문에, "지금 글을 쓰면 실제 지금 한국 시각이 정확히 반영되어 저장되고, 화면에는 항상 정확한 한국 시각으로 보인다"는 목표는 이미 완전히 이뤄진 상태입니다. Prisma Studio 등에서 보이는 `Z`가 붙은 표기는 그 값을 "사람이 읽는 도구"가 UTC 문자열로 표시해서 보여주는 방식일 뿐, 저장된 실제 순간 자체는 정확합니다.

**따라서 이번 항목은 별도의 코드 수정이 필요 없습니다.**

이 내용을 아래 내용으로 바꿔주세요.

```typescript
    } else if (e.key === "Backspace" && keywordWords[index] === "" && index > 0) {
      e.preventDefault();
      setKeywordWords((prev) => prev.filter((_, i) => i !== index));
      setTimeout(() => keywordInputRefs.current[index - 1]?.focus(), 0);
    }
  }

  // 키워드 칸의 'x' 버튼을 눌러서 그 칸을 지웁니다. 마지막 하나 남은 칸이면
  // (키워드를 하나도 입력하지 않은 상태로 만들기 위해) 완전히 없애지 않고 빈 칸으로 되돌립니다.
  function removeKeywordWord(index: number) {
    setKeywordWords((prev) => {
      if (prev.length === 1) return [""];
      return prev.filter((_, i) => i !== index);
    });
  }
```

**설명:** 키워드 칸이 하나만 남아있을 때 그 칸을 삭제하면, 배열 자체를 완전히 비우는 대신 빈 칸 하나(`[""]`)로 되돌립니다. 화면에는 항상 입력할 수 있는 빈 칸이 최소 하나는 남아있어야 자연스럽기 때문입니다. 말씀하신 것처럼 "키워드가 1개여도 삭제하면" 이 빈 칸 상태가 되고, 이 상태로 저장하면 키워드 없이 저장됩니다.

## 3단계: 프런트엔드 — 목록형 게시판, 행 전체를 클릭 가능하게 만들기

`frontend/src/app/(site)/boards/[code]/page.tsx` 파일을 여세요.

아래 내용을 찾으세요.

```tsx
                rows.map((row, idx) => (
                  <tr key={row.id} className="hover:bg-neutral-50">
                    <td className="whitespace-nowrap px-4 py-2.5 text-neutral-500">
                      {total - ((page - 1) * pageSize + idx)}
                    </td>
                    <td className="max-w-[320px] truncate px-4 py-2.5 font-medium">
                      <Link href={`/boards/${code}/${row.id}`} className="hover:underline">
                        {row.title}
                      </Link>
                    </td>
```

이 내용을 아래 내용으로 바꿔주세요.

```tsx
                rows.map((row, idx) => (
                  <tr
                    key={row.id}
                    onClick={() => router.push(`/boards/${code}/${row.id}`)}
                    className="cursor-pointer hover:bg-neutral-50"
                  >
                    <td className="whitespace-nowrap px-4 py-2.5 text-neutral-500">
                      {total - ((page - 1) * pageSize + idx)}
                    </td>
                    <td className="max-w-[320px] truncate px-4 py-2.5 font-medium">{row.title}</td>
```

**설명:** 이제까지는 `<td>` 안의 제목(`<Link>`)을 클릭했을 때만 이동했는데, 표의 각 행(`<tr>`)에 직접 `onClick`을 달아서 행 전체(어느 칸을 클릭하든) 클릭 시 상세 페이지로 이동하도록 바꿨습니다. `cursor-pointer`를 함께 넣어서, 마우스를 올렸을 때 이 행 전체가 클릭 가능하다는 것을 손 모양 커서로 알 수 있게 했습니다. 썸네일형(카드형) 게시판은 원래부터 카드 전체가 `<Link>`로 감싸져 있어서 이미 어디를 클릭해도 이동하고 있었으므로, 이번 수정은 목록형(표) 게시판에만 해당됩니다.
