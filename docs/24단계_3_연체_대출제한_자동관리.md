# 24단계 3: 회원 상태 확장('탈퇴') 및 연체 대출제한 자동 관리

## 목표

지금까지 회원 '상태'는 '활성' / '대기' / '정지' 세 가지였는데, '정지'가 "관리자가 직접 정지시킨 경우"와 "연체로 인한 대출제한"이라는 두 가지 의미를 함께 담고 있었습니다. 이번 단계에서는 상태를 이렇게 정리합니다.

- **활성**: 정상 이용 가능
- **정지**: 연체로 대출이 제한되었거나, 관리자가 직접 정지시킨 경우
- **탈퇴**(새로 추가): 회원이 진짜로 탈퇴한 경우. (지금은 홈페이지에 탈퇴 신청 기능이 없으니, 이번 단계에서는 관리자 화면에서만 '탈퇴' 상태로 바꿀 수 있게 만듭니다.)

그리고 "연체하면 그 일수만큼 대출이 제한되고, 제한 기간이 끝나면 자동으로 다시 '활성'이 되어야 한다"는 부분을 만듭니다. 말씀하신 대로 대출제한 내역을 저장하는 테이블을 새로 만들고, 두 가지 안전장치를 함께 넣습니다.

1. **매일 자정에 자동으로 실행되는 작업**: 대출제한이 끝났는데도 '정지' 상태로 남아있는 회원을 찾아서 자동으로 '활성'으로 되돌립니다.
2. **대출을 시도하는 바로 그 순간의 이중 확인**: 혹시 서버가 자정에 꺼져 있어서 1번 작업이 실행되지 못했더라도, 대출 처리 로직 안에서 "지금 이 회원의 대출제한이 정말 아직 유효한지" 대출제한 테이블을 직접 다시 확인합니다. 이미 끝난 대출제한인데 상태만 '정지'로 남아있다면, 이 순간 바로 '활성'으로 되돌리고 정상적으로 대출을 진행합니다.

이렇게 하면 자정 작업이 어쩌다 한 번 실행되지 않아도, 실제 대출 차단 여부는 항상 정확하게 판단됩니다.

추가로 두 가지를 반영합니다.

- 아직 반납하지 않은 대출 자료가 있는 회원은 상태를 '탈퇴'로 바꿀 수 없게 막습니다. (삭제가 막히는 것과 같은 이유입니다.)
- 개선44에서 만든 회원 삭제 확인 문구를, 말씀하신 새 문구로 바꿉니다.

실제로 반납할 때 연체를 계산해서 대출제한 기록을 만드는 기능(반납 처리 화면)은 다음 단계(24단계 4)에서 만듭니다. 이번 단계는 그 기능이 사용할 수 있는 "대출제한 테이블 + 자동 해제 + 이중 확인" 기반을 먼저 만들어두는 단계입니다.

## 3. 백엔드에 새 파일 만들기: `loan-restrictions.service.ts`

`C:\projects\LibraryNearMe\backend\src` 안에 `loan-restrictions`라는 새 폴더를 만들고, 그 안에 `loan-restrictions.service.ts` 파일을 새로 만드세요. (경로: `C:\projects\LibraryNearMe\backend\src\loan-restrictions\loan-restrictions.service.ts`)

아래 내용을 그대로 넣으세요.

```ts
import { Injectable, Logger } from '@nestjs/common';
import { Cron, CronExpression } from '@nestjs/schedule';
import { PrismaService } from '../prisma.service';

@Injectable()
export class LoanRestrictionsService {
  private readonly logger = new Logger(LoanRestrictionsService.name);

  constructor(private prisma: PrismaService) {}

  // 대출제한 기록을 새로 만들고, 회원 상태를 '정지'로 바꿉니다.
  // (실제로 이 함수를 호출하는 "반납 처리(연체 계산)" 기능은 다음 단계에서 만듭니다.)
  async createRestriction(libraryId: number, userId: number, endDate: Date, reason?: string) {
    const [restriction] = await this.prisma.$transaction([
      this.prisma.loanRestriction.create({
        data: { libraryId, userId, endDate, reason },
      }),
      this.prisma.user.update({
        where: { id: userId },
        data: { status: 'SUSPENDED' },
      }),
    ]);
    return restriction;
  }

  // 지금 이 회원에게 아직 끝나지 않은(유효한) 대출제한이 있는지 확인합니다.
  async findActiveRestriction(libraryId: number, userId: number) {
    const now = new Date();
    return this.prisma.loanRestriction.findFirst({
      where: { libraryId, userId, endDate: { gte: now } },
      orderBy: { endDate: 'desc' },
    });
  }

  // 매일 자정에 자동으로 실행됩니다: 대출제한이 끝났는데도 '정지' 상태로 남아있는 회원을 찾아 '활성'으로 되돌립니다.
  @Cron(CronExpression.EVERY_DAY_AT_MIDNIGHT)
  async releaseExpiredRestrictions() {
    const now = new Date();
    const suspendedUsers = await this.prisma.user.findMany({
      where: { status: 'SUSPENDED' },
      select: { id: true },
    });

    let releasedCount = 0;
    for (const u of suspendedUsers) {
      const stillActive = await this.prisma.loanRestriction.findFirst({
        where: { userId: u.id, endDate: { gte: now } },
      });
      if (!stillActive) {
        await this.prisma.user.update({ where: { id: u.id }, data: { status: 'ACTIVE' } });
        releasedCount++;
      }
    }

    if (releasedCount > 0) {
      this.logger.log(`대출제한이 끝난 회원 ${releasedCount}명을 '활성' 상태로 되돌렸습니다.`);
    }
  }
}
```
