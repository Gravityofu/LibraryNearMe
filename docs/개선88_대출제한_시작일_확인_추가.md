# 개선88: 대출제한 확인 시 "시작일이 아직 안 됐는지"도 함께 확인하기

## 목표

방금 확인하신 대로, 유저1의 정지 이력은 "2026년 7월 31일부터 2026년 7월 31일까지" 딱 하루짜리 기록입니다. 그런데 그보다 하루 이른 2026년 7월 30일로 대출일을 지정해서 대출을 시도했더니 "대출 제한 중입니다"라며 거부되었습니다. 이건 잘못된 동작이 맞습니다.

원인을 찾아보니, 지금 대출제한이 "지금 유효한지" 확인하는 코드(`findActiveRestriction`)는 "제한 마지막 날(`endDate`)이 아직 지나지 않았는지"만 확인하고, "제한이 이미 시작됐는지(`startDate`가 지났는지)"는 전혀 확인하지 않고 있었습니다. 그래서 "7월 31일부터"라는 기록이 있으면, 그보다 이전 날짜(7월 30일)를 기준으로 확인하더라도 "아직 안 끝났으니 제한 중"이라고 잘못 판단해버린 것입니다. 이 가이드는 "제한이 이미 시작된 경우에만" 유효한 것으로 보도록 조건을 하나 추가합니다.

## 1단계: `loan-restrictions.service.ts` 수정하기

`backend/src/loan-restrictions/loan-restrictions.service.ts` 파일을 여세요.

아래 내용을 찾으세요.

```typescript
  async findActiveRestriction(libraryId: number, userId: number, asOf?: Date) {
    const baseline = asOf ? this.dayStart(asOf) : this.todayStart();
    return this.prisma.loanRestriction.findFirst({
      where: { libraryId, userId, endDate: { gte: baseline } },
      orderBy: { endDate: 'desc' },
    });
  }
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
  async findActiveRestriction(libraryId: number, userId: number, asOf?: Date) {
    const baseline = asOf ? this.dayStart(asOf) : this.todayStart();

    // "제한 마지막 날이 아직 지나지 않은" 기록들을 먼저 가져온 뒤,
    // 그중에서 "시작일이 이미 지났거나 오늘인" 것만 남깁니다.
    // (시작일은 등록 시각까지 함께 저장되어 있어서, 날짜만 비교하도록 dayStart로 맞춰서 비교합니다.)
    const candidates = await this.prisma.loanRestriction.findMany({
      where: { libraryId, userId, endDate: { gte: baseline } },
      orderBy: { endDate: 'desc' },
    });
    return candidates.find((r) => this.dayStart(r.startDate) <= baseline) || null;
  }
```

**설명:** 이전에는 "제한 마지막 날이 안 지났는지"만 확인해서, 아직 시작하지도 않은 미래의 제한 기록까지 "지금 제한 중"으로 잘못 판단할 수 있었습니다. 이제는 후보 기록들 중에서 "시작일이 기준 날짜(`baseline`)보다 늦지 않은 것"(즉, 이미 시작된 것)만 골라서 그중 가장 나중에 끝나는 기록을 돌려줍니다. `dayStart`로 시작일의 시:분:초를 없애고 날짜만 비교하기 때문에, 오늘 등록한 제한(시작 시각이 오후 3시든 몇 시든)은 오늘 기준으로 정상적으로 "이미 시작됨"으로 인식됩니다.
