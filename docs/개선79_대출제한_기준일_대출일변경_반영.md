# 개선79: 대출 처리 시 대출제한 확인 기준일을 '대출일 변경' 날짜로 맞추기

## 목표

지금은 대출 처리를 할 때 "이 회원에게 아직 유효한 대출제한이 있는가?"를 확인하는 기준 날짜가 항상 **실제 서버의 오늘 날짜**입니다. 그런데 관리자가 '대출/반납일 변경' 기능으로 대출일을 다른 날짜(예: 과거 날짜)로 지정해서 대출을 처리하는 경우에는, 대출제한이 풀렸는지도 그 **지정한 날짜** 기준으로 판단하는 것이 맞습니다.

이 가이드는 대출 처리 로직에서만 이 기준을 "지정한 대출일(없으면 실제 오늘)"로 바꿉니다. 그 외의 용도(정지 이력에서 "지금 진행 중"인지 주황색으로 표시하는 것, 매일 자정 자동으로 정지를 풀어주는 작업 등)는 지금처럼 그대로 실제 서버의 오늘 날짜를 기준으로 유지됩니다.

> 참고: 반납 처리 기능은 아직 이 시스템에 구현되어 있지 않습니다. 나중에 반납 처리 기능을 만들 때, 이번에 만드는 것과 같은 방식(지정한 날짜를 기준으로 사용)을 적용하면 됩니다.

## 1단계: `loan-restrictions.service.ts` 수정 — 기준 날짜를 바꿀 수 있게 만들기

`backend/src/loan-restrictions/loan-restrictions.service.ts` 파일을 여세요.

아래 내용을 찾으세요.

```typescript
  // 오늘 날짜의 자정(00:00) 시각을 구합니다.
  // "제한 마지막 날"은 그 날짜 하루 전체 동안은 계속 막혀 있어야 하므로, 시:분:초가 섞인
  // "지금 이 순간"이 아니라 "오늘 날짜(자정 기준)"으로 비교해야 정확합니다.
  private todayStart(): Date {
    const d = new Date();
    d.setUTCHours(0, 0, 0, 0);
    return d;
  }

  // 지금 이 회원에게 아직 끝나지 않은(유효한) 대출제한이 있는지 확인합니다.
  // "제한 마지막 날"이 오늘이거나 오늘보다 나중이면 아직 제한 중인 것으로 봅니다.
  async findActiveRestriction(libraryId: number, userId: number) {
    const today = this.todayStart();
    return this.prisma.loanRestriction.findFirst({
      where: { libraryId, userId, endDate: { gte: today } },
      orderBy: { endDate: 'desc' },
    });
  }
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
  // 주어진 날짜의 자정(00:00) 시각을 구합니다.
  // "제한 마지막 날"은 그 날짜 하루 전체 동안은 계속 막혀 있어야 하므로, 시:분:초가 섞인
  // "그 순간"이 아니라 "날짜(자정 기준)"으로 비교해야 정확합니다.
  private dayStart(date: Date): Date {
    const d = new Date(date);
    d.setUTCHours(0, 0, 0, 0);
    return d;
  }

  // 오늘 날짜의 자정(00:00) 시각을 구합니다.
  private todayStart(): Date {
    return this.dayStart(new Date());
  }

  // 지금 이 회원에게 아직 끝나지 않은(유효한) 대출제한이 있는지 확인합니다.
  // "제한 마지막 날"이 기준일이거나 기준일보다 나중이면 아직 제한 중인 것으로 봅니다.
  //
  // asOf: 기준으로 삼을 날짜입니다. 넘기지 않으면 실제 오늘 날짜를 기준으로 확인합니다.
  // (대출 처리에서 '대출/반납일 변경'으로 다른 날짜를 지정한 경우, 그 날짜를 여기로 넘겨서
  //  "그 날짜 기준으로 대출제한이 풀렸는지"를 확인할 수 있습니다. 정지 이력 화면에 "지금 진행
  //  중"인지 표시하거나, 매일 자정 자동 해제 작업처럼 실제 오늘 날짜가 필요한 곳에서는
  //  asOf 없이 그대로 호출하면 됩니다.)
  async findActiveRestriction(libraryId: number, userId: number, asOf?: Date) {
    const baseline = asOf ? this.dayStart(asOf) : this.todayStart();
    return this.prisma.loanRestriction.findFirst({
      where: { libraryId, userId, endDate: { gte: baseline } },
      orderBy: { endDate: 'desc' },
    });
  }
```

**설명:** `dayStart()`라는 새 함수를 만들어서, "주어진 아무 날짜"를 자정 기준으로 만들 수 있게 했습니다. `todayStart()`는 이제 이 `dayStart()`에 오늘 날짜를 넣어서 쓰는 방식으로 바뀌었습니다(동작은 이전과 똑같습니다). 그리고 `findActiveRestriction` 함수에 `asOf`라는 선택 항목(파라미터)을 추가해서, 이 값을 넘기면 그 날짜를 기준으로, 넘기지 않으면 지금처럼 실제 오늘 날짜를 기준으로 확인하도록 했습니다. 기존에 이 함수를 부르던 다른 코드(정지 이력 자동 상태 정리 등)는 `asOf`를 넘기지 않으므로 지금까지와 똑같이 동작합니다.

## 2단계: `loans.service.ts` 수정 — 대출 처리 시 지정한 대출일을 기준으로 확인하기

`backend/src/loans/loans.service.ts` 파일을 여세요.

아래 내용을 찾으세요.

```typescript
    const activeRestriction = await this.loanRestrictionsService.findActiveRestriction(libraryId, userId);
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
    // '대출/반납일 변경'으로 대출일을 다른 날짜로 지정했다면, 대출제한이 풀렸는지도 그 날짜를
    // 기준으로 확인합니다. 지정하지 않았다면(loanDateOverride가 없다면) 실제 오늘 날짜를 기준으로 확인합니다.
    const activeRestriction = await this.loanRestrictionsService.findActiveRestriction(
      libraryId,
      userId,
      loanDateOverride,
    );
```

**설명:** `createLoan` 함수는 원래 `loanDateOverride`(관리자가 지정한 대출일)를 파라미터로 받고 있었지만, 지금까지는 대출제한을 확인할 때 이 값을 쓰지 않고 항상 실제 오늘 날짜로만 확인했습니다. 이제 이 값을 그대로 `findActiveRestriction`에 넘겨서, 지정한 날짜가 있으면 그 날짜 기준으로, 없으면(즉 일반적인 "오늘 대출 처리") 실제 오늘 날짜 기준으로 확인하도록 바뀝니다.
