# 개선86: 시스템 전체의 시간 기준을 한국 시간(KST)으로 통일하기

## 목표

지금 서버는 대부분 UTC(협정 세계시) 기준으로 "오늘 날짜"와 "지금 시각"을 계산하고 있습니다. 평소에는 잘 드러나지 않지만, 한국 시간 기준 자정부터 오전 9시 사이에는 UTC 날짜가 아직 어제 날짜이기 때문에, 이 시간대에 대출/반납을 처리하면 "오늘 날짜"가 실제로는 어제 날짜로 계산되는 등 미묘한 오류가 생길 수 있습니다. 그리고 개선83에서 저장하기 시작한 대출/반납 시각도 UTC 기준이라, 데이터베이스에서 직접 확인하면 한국 시간보다 9시간 이른 시각으로 보입니다.

이 가이드는 서버가 실행되는 시간대를 한국 시간(Asia/Seoul)으로 맞추고, 날짜/시각을 계산하는 부분들이 전부 이 한국 시간을 기준으로 동작하도록 고칩니다. 이렇게 하면 서버가 실제로 어느 나라의 컴퓨터에서 돌아가고 있든, "오늘"과 "지금"은 항상 한국 기준으로 계산됩니다.

```typescript
function combineDateWithNow(date: Date): Date {
  const now = new Date();
  const combined = new Date(date);
  combined.setUTCHours(now.getUTCHours(), now.getUTCMinutes(), now.getUTCSeconds(), now.getUTCMilliseconds());

}
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
function combineDateWithNow(date: Date): Date {
  const now = new Date();
  const combined = new Date(date);
  // 1단계에서 서버 시간대를 한국 시간으로 맞췄으므로, getHours() 등은 이제 한국 시간 기준입니다.
  combined.setHours(now.getHours(), now.getMinutes(), now.getSeconds(), now.getMilliseconds());
  return combined;
}
```

**설명:** `setUTCHours`/`getUTCHours`(항상 협정 세계시 기준) 대신 `setHours`/`getHours`(서버의 시간대 설정을 따름)를 쓰도록 바꿨습니다. 1단계에서 서버 시간대를 한국 시간으로 맞췄기 때문에, 이제 이 함수는 실제 처리한 한국 시간(시:분:초)을 정확히 기록합니다.


이 내용을 아래 내용으로 바꿔주세요.

```typescript
  private dayStart(date: Date): Date {
    const d = new Date(date);
    // 1단계에서 서버 시간대를 한국 시간으로 맞췄으므로, setHours(0, 0, 0, 0)은
```

**설명:** 대출제한이 "지금 유효한지" 판단할 때 기준으로 삼는 "오늘 자정"이 이제 한국 시간 자정을 의미하게 됩니다. 이 함수를 쓰는 `findActiveRestriction`, 매일 자정 자동으로 정지를 풀어주는 작업(`releaseExpiredRestrictions`) 모두 자동으로 한국 시간 기준으로 동작합니다. (참고로 매일 자정 자동 실행 작업도 이제 한국 시간 자정에 실행됩니다. 지금까지는 UTC 자정, 즉 한국 시간 오전 9시에 실행되고 있었습니다.)

## 4단계: 프런트엔드 — `loans/page.tsx`의 날짜 계산을 한국 시간 기준으로 맞추기

`frontend/src/app/admin/loans/page.tsx` 파일을 여세요. 관리자가 쓰는 컴퓨터의 시간대 설정과 상관없이 항상 한국 시간을 기준으로 계산하도록 고칩니다.

### 4-1. "오늘 날짜" 계산하기

아래 내용을 찾으세요.

```typescript
function todayStr() {
  return new Date().toISOString().slice(0, 10);
}
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
// 한국 시간(KST, UTC+9) 기준으로 오늘 날짜를 "YYYY-MM-DD" 형식으로 돌려줍니다.
// 이 화면을 보는 컴퓨터의 시간대 설정과 상관없이, 항상 한국 시간 기준으로 계산합니다.
function todayStr() {
  return new Date().toLocaleDateString("en-CA", { timeZone: "Asia/Seoul" });
}
```

**설명:** `toISOString()`은 항상 협정 세계시 기준 날짜를 돌려주기 때문에, 한국 시간 새벽 0시~9시 사이에는 실제로는 오늘인데도 어제 날짜가 나오는 문제가 있었습니다. `toLocaleDateString("en-CA", { timeZone: "Asia/Seoul" })`는 명시적으로 한국 시간대를 기준으로 계산하고, `en-CA`(캐나다 영어) 표기 방식은 마침 "YYYY-MM-DD" 형식이라 그대로 쓸 수 있습니다.

### 4-2. "오늘 자정" 계산 함수의 이름과 내용을 고치기

아래 내용을 찾으세요.

```typescript
  // 오늘 날짜의 자정(00:00) 시각을 구합니다. 백엔드와 같은 기준으로 "지금 제한 중인지"를 판단하기 위함입니다.
  function todayStartUTC() {
    const d = new Date();
    d.setUTCHours(0, 0, 0, 0);
    return d;
  }
```

이 내용을 아래 내용으로 바꿔주세요.

```typescript
  // 한국 시간 기준 오늘 자정(00:00 KST)에 해당하는 실제 시각을 구합니다.
  // 백엔드와 같은 기준(한국 시간)으로 "지금 제한 중인지"를 판단하기 위함입니다.
  function todayStartKST() {
    return new Date(todayStr() + "T00:00:00+09:00");
  }
```

**설명:** 함수 이름을 `todayStartUTC`에서 `todayStartKST`로 바꿔서, 이제 협정 세계시가 아니라 한국 시간 기준이라는 걸 이름만 보고도 알 수 있게 했습니다. `"T00:00:00+09:00"`은 "한국 시간대(UTC+9) 기준으로 00시 00분"이라는 뜻이라, 이 화면을 보는 컴퓨터의 시간대 설정과 상관없이 항상 정확한 한국 시간 자정을 구할 수 있습니다.
