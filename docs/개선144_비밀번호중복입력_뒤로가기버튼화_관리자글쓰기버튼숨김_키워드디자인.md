# 개선144. 비밀번호 중복 입력 수정 / 뒤로 가기 버튼화 / 관리자 글쓰기 버튼 숨김 / 키워드 영역 디자인 정리

## 목표

개선143 적용 후 알려주신 4가지를 처리합니다.

1. 비회원이 글 수정을 위해 비밀번호를 입력할 때, 한 번에 인식되지 않고 두 번째 입력해야 인식되는 문제를 고칩니다.
2. "이 글을 수정할 권한이 없습니다" 화면의 "목록으로" **링크**를 **버튼** 모양으로 바꿉니다.
3. 관리자 페이지 게시판 설정과 상관없이, 관리자 계정으로 로그인했을 때는 홈페이지 어떤 게시판에서도 "글쓰기" 버튼 자체가 보이지 않게 합니다.
4. 홈페이지 글 상세 화면의 회색 정보 상자 디자인을 정리합니다. 가로줄이 상자 끝까지 이어지게 하고, 회색 배경은 가로줄까지만 나오게 하고, 키워드는 가로줄 아래 이탤릭·굵은 글씨로 도서관 색상으로 표시하며, 키워드가 없어도 같은 높이만큼 빈 공간을 두어서 본문이 항상 같은 위치에서 시작하게 합니다.

---

## 1번 문제의 원인

`frontend/src/app/(site)/boards/[code]/write/page.tsx`에서, 수정 화면에 들어오면 `useEffect`가 `loadExistingPostForEdit()` 함수를 실행하고 이 함수 안에서 `window.prompt(...)`로 비밀번호를 물어봅니다.

그런데 Next.js 개발 서버는 기본적으로 "리액트 스트릭트 모드(Strict Mode)"라는 안전장치가 켜져 있어서, **개발 중에는** 같은 화면의 `useEffect`를 화면에 보이지 않게 한 번 껐다가 다시 켜면서 **두 번 실행**합니다. (버그를 미리 찾아내라고 리액트가 일부러 그렇게 만들어 둔 개발 전용 동작입니다.) 이 때문에 비밀번호를 물어보는 `window.prompt`도 두 번 실행되는데, 첫 번째 실행 결과는 두 번째 실행이 화면 상태를 새로 만들면서 덮어써 버려서, 마치 "처음 입력한 건 무시되고 두 번째 입력만 인식되는" 것처럼 보이는 것입니다. (실제 서비스로 배포했을 때는 이 안전장치가 꺼지기 때문에 원래는 잘 드러나지 않는 문제인데, 미리 고쳐두는 게 안전합니다.)

**해결 방법**: 같은 글(postId)에 대해서는 딱 한 번만 비밀번호를 물어보도록, "이미 확인한 글 번호"를 기억하는 장치를 추가합니다.

## 확인하기

1. **비밀번호 중복 입력 (1번)**: 비회원 글을 수정하려고 "수정" 버튼을 누르고, 올바른 비밀번호를 **한 번만** 입력해서 정상적으로 수정 화면이 열리는지 확인합니다. (비밀번호 창이 두 번 뜨지 않아야 합니다.)
2. **뒤로 가기 버튼 (2번)**: 비회원 글 수정 시 비밀번호를 일부러 틀리게 입력해서 "이 글을 수정할 권한이 없습니다" 화면을 띄우고, "목록으로"가 링크가 아니라 테두리 있는 버튼 모양으로 보이는지 확인합니다.
3. **관리자 글쓰기 버튼 숨김 (3번)**: 관리자 계정으로 로그인한 상태에서, "회원 글쓰기"가 가능으로 설정된 게시판과 불가능으로 설정된 게시판 모두에서 홈페이지 게시판 목록 화면에 "글쓰기" 버튼이 전혀 보이지 않는지 확인합니다. 로그아웃하거나 일반 회원으로 로그인하면 "회원 글쓰기"가 가능인 게시판에서는 다시 "글쓰기" 버튼이 보여야 합니다.
4. **키워드 영역 디자인 (4번)**: 키워드가 있는 글과 없는 글(비회원 글 등)을 각각 열어서, 회색 배경이 가로줄까지만 나오고, 가로줄이 상자 끝까지 이어지며, 본문이 시작하는 위치가 두 글 모두 똑같은 높이에서 시작하는지 확인합니다. 키워드가 있는 글에서는 굵은 이탤릭체로 도서관 색상 키워드가 잘 보이는지도 확인합니다.
