# 개선154. 썸네일 사진 영역 크기를 확실하게 고정하기

## 목표

개선151·152·153을 거쳤는데도 가로형(한 줄 3개) 게시판에서 사진 비율에 따라 제목·본문 위치가 계속 달라지는 문제를, 이번에는 **원리 자체를 바꿔서** 확실하게 해결합니다.

## 원인 (이번에 다시 찾은 것)

지금 사진 상자는 `aspect-[16/9]` 같은 "가로세로 비율" 방식으로 높이를 정하고 있습니다. 그런데 이 방식에는 함정이 하나 있습니다. **비율로 정한 높이보다 상자 안의 내용(사진)이 더 크면, 상자가 비율을 무시하고 내용 크기만큼 늘어납니다.** (CSS에서 비율 지정은 "최소 크기"를 넘어서까지 강제하지는 못하기 때문입니다.)

사진에 `h-full`(높이 100%)을 줬지만, 이 100%가 기준으로 삼아야 할 부모 상자의 높이 자체가 "비율로 계산된 값"이라 브라우저나 상황에 따라 제대로 계산되지 않는 경우가 있습니다. 그러면 사진은 자기 원래 높이로 그려지고, 그만큼 상자가 늘어나서 → 세로가 긴 사진일수록 상자가 커지고 → 그 아래 제목·본문이 밀려 내려갑니다. 정확히 지금 겪고 계신 증상입니다.

세로형(한 줄 4개)에서 문제가 덜 보였던 것도 같은 이유입니다. 세로형 상자는 원래 세로로 길기 때문에 사진이 상자보다 커지는 경우가 드물었을 뿐, 근본 원인은 똑같았습니다.

## 해결 방법

비율 지정 대신, **여백(padding)으로 상자 높이를 만들고, 사진은 그 상자 위에 겹쳐 놓는 방식**으로 바꿉니다. 이 방식은 옛날부터 쓰이던 가장 확실한 방법으로, 상자 안의 사진이 아무리 크든 작든 상자 높이에 **전혀 영향을 줄 수 없습니다.** 사진이 상자 크기를 밀어낼 방법 자체가 없어지는 것입니다.

또한 높이 계산을 Tailwind(스타일 도구)의 이름 붙은 기능에 맡기지 않고 숫자로 직접 지정하기 때문에, 개선152에서 의심했던 "스타일이 만들어지지 않는" 문제도 원천적으로 없어집니다.

## 수정 방법

`frontend/src/app/(site)/boards/[code]/page.tsx` 파일을 여세요.

아래 코드를 찾으세요. (240줄 부근, 카드 목록 안에 있습니다)

```typescript
                <div className={`w-full bg-white ${isTallThumbnail ? "aspect-[3/4]" : "aspect-[16/9]"}`}>
                  {row.thumbnailUrl ? (
                    // eslint-disable-next-line @next/next/no-img-element
                    <img src={row.thumbnailUrl} alt="" className="h-full w-full object-contain" />
                  ) : (
                    <div className="flex h-full w-full items-center justify-center bg-neutral-100 text-xs text-neutral-300">
                      {t("boards.list.col.thumbnail")}
                    </div>
                  )}
                </div>
```

아래로 통째로 바꿔주세요.

```typescript
                <div
                  className="relative w-full shrink-0 overflow-hidden bg-white"
                  style={{ paddingTop: isTallThumbnail ? "133.33%" : "56.25%" }}
                >
                  {row.thumbnailUrl ? (
                    // eslint-disable-next-line @next/next/no-img-element
                    <img
                      src={row.thumbnailUrl}
                      alt=""
                      className="absolute inset-0 h-full w-full object-contain"
                    />
                  ) : (
                    <div className="absolute inset-0 flex items-center justify-center bg-neutral-100 text-xs text-neutral-300">
                      {t("boards.list.col.thumbnail")}
                    </div>
                  )}
                </div>
```

### 무엇이 바뀌었는지

- `aspect-[3/4]` / `aspect-[16/9]` (비율 지정) → `paddingTop: "133.33%"` / `"56.25%"` (위쪽 여백으로 높이 만들기)로 바꿨습니다. CSS에서 위아래 여백을 %로 주면 **가로 너비를 기준으로** 계산되기 때문에, 가로 너비의 56.25%(= 9÷16)만큼 높이가 생기면 정확히 16:9 상자가 됩니다. 마찬가지로 133.33%(= 4÷3)는 정확히 3:4 상자입니다. **보이는 비율은 지금과 완전히 똑같고, 계산 방식만 확실한 쪽으로 바꾼 것입니다.**
- `relative`와 `absolute inset-0`을 추가했습니다. 사진(또는 '사진 없음' 회색 안내)이 상자 안에 **떠 있는 상태로 겹쳐지기** 때문에, 사진 크기가 상자 높이를 밀어낼 수 없게 됩니다. 이것이 이번 수정의 핵심입니다.
- `shrink-0`을 추가했습니다. 카드 안에서 사진 상자가 눌려서 줄어드는 경우까지 막아줍니다.
- `overflow-hidden`을 추가했습니다. 혹시라도 사진이 상자 밖으로 삐져나오면 잘라내서, 카드 모서리 둥근 모양도 깔끔하게 유지됩니다.
- `object-contain`(사진 전체가 잘리지 않고 보이게, 남는 자리는 흰 여백)과 가운데 정렬은 그대로 유지됩니다.

## 확인하기 (중요)

수정 후 화면이 그대로라면, 브라우저에 옛날 스타일이 남아있는 것일 수 있습니다. 아래 순서대로 해주세요.

1. 프런트엔드 개발 서버를 완전히 껐다가 다시 켭니다. (`Ctrl+C`로 끄고 `npm run dev`)
2. 브라우저에서 `Ctrl+Shift+R`(강력 새로고침)로 페이지를 다시 불러옵니다.
3. "열린 게시판"(가로형, 한 줄 3개)을 엽니다. 가로가 긴 사진 글과 세로가 긴 사진 글을 나란히 두고, **사진 상자의 높이가 서로 완전히 같은지** 확인합니다.
4. 제목이 시작하는 위치가 모든 카드에서 같은 높이인지 확인합니다.
5. 사진이 잘리지 않고 전체가 보이며, 남는 공간이 흰색인지 확인합니다.
6. 세로형(한 줄 4개) 게시판도 똑같이 잘 나오는지 확인합니다.
7. 사진을 첨부하지 않은 글은 회색 안내 상자가 그대로 나오는지 확인합니다.
