# 개선78: 파일 줄바꿈(CRLF/LF) 문제 정리하기

## 목표

지금 `git status`를 실행하면 개선77과 상관없는 파일 수십 개(`README.md`, `backend/src` 안의 여러 파일들 등)가 전부 "수정됨"으로 나타납니다. 실제 코드 내용을 확인해보면 아무것도 바뀐 게 없고, 줄바꿈 방식(Windows의 CRLF ↔ Unix/GitHub의 LF)만 다르게 저장되어 있어서 git이 "변경됨"으로 착각하고 있는 것입니다.

이 가이드는 두 가지를 합니다.

1. 앞으로는 이런 일이 다시 생기지 않도록, "이 저장소의 텍스트 파일은 항상 LF로 저장한다"는 규칙을 저장소에 등록합니다. (`.gitattributes` 파일)
2. 지금 뒤섞여 있는 기존 파일들의 줄바꿈을 규칙에 맞게 한 번 정리합니다.

이 작업은 코드의 동작(기능)을 바꾸는 것이 아니라, 파일 저장 방식만 통일하는 작업입니다. 그래서 이 가이드를 적용해도 도서관 시스템의 화면이나 기능은 전혀 달라지지 않습니다.

---

## 1단계: `.gitattributes` 파일 만들기

`C:\projects\LibraryNearMe` 폴더(프로젝트 최상위, `backend`/`frontend` 폴더와 같은 위치)에 `.gitattributes`라는 이름의 새 파일을 만들고, 아래 내용을 그대로 입력해 주세요.

> 메모장이나 VSCode에서 새 파일을 만들 때 파일 이름을 정확히 `.gitattributes`로 입력해야 합니다. (점으로 시작하고, 확장자가 없는 이름입니다.)

```
* text=auto eol=lf
```

**설명:** 이 한 줄은 git에게 "모든 텍스트 파일은 GitHub 저장소에 저장될 때 항상 LF 방식의 줄바꿈을 쓴다"고 알려주는 설정입니다. 여러분이 Windows에서 파일을 열어서 편집할 때는 평소처럼 편집하면 되고, git이 저장(커밋)할 때 자동으로 LF로 맞춰줍니다. 이 파일 하나만 있으면 앞으로 같은 팀의 누가 어떤 운영체제(Windows/Mac)에서 작업하더라도 줄바꿈이 뒤섞이는 문제가 생기지 않습니다.

---

## 2단계: git 설정 확인하기

터미널(명령 프롬프트)을 열고 아래 명령어를 실행해 주세요.

```
git config --global core.autocrlf true
```

**설명:** 이 설정은 Windows 컴퓨터에서 "파일을 내려받을 때는 Windows 방식(CRLF)으로 바꿔서 보여주고, 커밋할 때는 다시 LF로 저장한다"는 뜻입니다. 방금 만든 `.gitattributes` 파일과 함께 쓰면, 여러분은 평소처럼 파일을 편집하기만 하면 되고 줄바꿈 관리는 git이 알아서 해줍니다. (이 설정은 `--global`이므로 이 컴퓨터의 모든 git 저장소에 적용됩니다. 이미 설정되어 있었다면 그대로 유지되니 다시 실행해도 문제 없습니다.)

---

## 3단계: 기존 파일들의 줄바꿈 정리하기

이제 지금까지 뒤섞여 있던 기존 파일들을 방금 정한 규칙(LF)에 맞게 한 번 정리해야 합니다. 아래 명령어를 순서대로 실행해 주세요.

```
cd C:\projects\LibraryNearMe
git add --renormalize .
```

**설명:** `--renormalize` 옵션은 "지금 저장소에 있는 모든 파일을 `.gitattributes` 규칙에 맞춰 다시 검사해서, 실제로 내용이 바뀐 파일이 아니라 줄바꿈 방식만 다른 파일들은 규칙에 맞게 정리해라"라는 뜻입니다. 이 명령어를 실행해도 파일의 실제 코드 내용(글자)은 전혀 바뀌지 않고, 저장 방식(줄바꿈)만 통일됩니다.

---

## 확인하기

아래 명령어로 결과를 확인해 주세요.

```
git status
```

이제는 실제로 의미 있게 바뀐 파일들(개선77에서 작업한 `loan-restrictions.controller.ts`, `loan-restrictions.service.ts`, `members/page.tsx`, `dictionary.ts`, 그리고 새로 만든 `.gitattributes`)만 "수정됨" 또는 "새 파일"로 나타나야 합니다. 이전처럼 `README.md`나 다른 무관한 파일들이 잔뜩 나타나지 않는다면 정상적으로 정리된 것입니다.

혹시 여전히 관련 없는 파일들이 "수정됨"으로 남아있다면, 그 파일 이름을 알려주시면 원인을 다시 확인해 드리겠습니다.
